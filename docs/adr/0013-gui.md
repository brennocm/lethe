# 0013. GUI module

- Status: accepted
- Date: 2026-11-16

## Context
M13 delivers `lethe-gui` (spec §16): the tray, the panel, the full-screen alert and passphrase
entry, in a separate cgo module. Four points were in tension with the rest of the spec:

- §241 says `run` "opens the GUI", but lethe never executes another program (principle 10;
  privsep only re-executes `/proc/self/exe`);
- §20.3 lets the GUI import only `contracts` and `ipc`, while the IPC answer types lived in
  `daemon` and the texts in `i18n`;
- Fyne's `Entry` keeps the passphrase in a string;
- Fyne cannot tell whether the compositor gave the alert window focus, which §16.4 asks to
  record.

## Decision
- **Who opens the GUI.** The session agent opens it, because it already runs as the operator
  on the session bus. It asks the user's systemd for a transient unit
  (`org.freedesktop.systemd1.Manager.StartTransientUnit`, `lethe-gui-<pid>.service`), and the
  unit stops when the agent ends. `run` passes the path in `LETHE_GUI`, only when:
  - there is a `lethe-gui` next to the binary;
  - it is a regular file (not a symlink), executable, not writable by group or others, and
    owned by root or the operator;
  - neither `--no-gui` nor `--tui` was given.

  The agent checks the file again before asking. When the file is missing, or there is no
  systemd user manager, the operator is told, and alerts stay on the agent's notifications and
  the terminal. Nothing becomes fatal, and nothing silently goes without an alert surface. The
  GUI still runs by hand (`lethe-gui --socket …`).
- **Boundary.** The IPC answers (`Status`, `AlertView`, `ExitView`, `Lockdown`, `QueryParams`,
  `DisarmResult`, `Selftest*`, `FullscreenReport`) move to `internal/contracts`, and
  `internal/daemon` keeps aliases. The GUI imports `contracts`, `ipc` and `i18n`; the operator
  texts are embedded data with no I/O, and duplicating them would split the source. A test in
  the GUI module walks every file and fails on any other `lethe/internal/...` import. The
  restrictive reading of the spec stands for everything else (daemon, guard, sensors).
- **Passphrase.** `SecretEntry` is a focusable widget that keeps the bytes in a fixed, mlocked
  256-byte buffer and draws only dots. `Take` hands over an mlocked copy and wipes the entry;
  the caller wipes the copy after deriving the key. Fyne's `Entry` is used only for the reason
  and the filters. On X11 (`XDG_SESSION_TYPE=x11`, or `DISPLAY` without `WAYLAND_DISPLAY`) every
  passphrase prompt warns that same-UID programs can read the keyboard and suggests the
  terminal (§22 item 12).
- **Full-screen alert:**
  - it shows the oldest open, unacknowledged CRITICAL, with the same content as the TUI;
  - `SetCloseIntercept` swallows the close button, and Esc does nothing;
  - only Acknowledge with a reason and the passphrase closes it, or the alert resolving;
  - the window asks for full screen and focus.
- **Reporting the alert.** The new IPC method `gui.fullscreen_result` (safe) reports
  `focused | shown | failed` and the latency since the GUI first saw the alert. The GUI reports
  `shown`, because Fyne cannot see the compositor's focus. The daemon journals it as
  `response.executed` of `alert_fullscreen` with `reported_by: gui`, once per alert: a peer
  with the same UID can add one record and change no state. The list of event types does not
  grow.
- **Panel and tray:**
  - the panel holds the header (state, guard, session, time, fingerprint, exit, lockdown), a
    grid with one card per category, a timeline filtered by minimum severity and check prefix,
    and the buttons Panic (red, with confirmation), Leave panic (in PANIC only), Selftest
    (complete or quick), Acknowledge and Disarm;
  - the tray icon is a disc in the state colour with the open-alert count; its menu has
    Open panel, Panic, Selftest and Disarm;
  - closing the panel hides it while the tray exists.
- **No "ok" for what nothing watches.** The grid lists the checks that have texts, so
  `internal/i18n` may only hold checks in the registry; a test enforces this. DNS-002 and
  DNS-003 lose their texts until they exist.
- **Build and tests.** `go.work` serves editors; the tasks run with `GOWORK=off`, so the core's
  `./...` never reaches the cgo module.
  - `mise run check` includes `check:gui`: lint, vet and tests of `internal/gui` without cgo.
    The tests use the Fyne test driver, with markup goldens of the panel and the alert window,
    and the flows ack, panic, disarm and selftest against a fake backend.
  - `check:all` adds race and govulncheck for the module.
  - `main` (GLFW) needs the OpenGL/X11/Wayland headers and builds in the `gui` CI job
    (`mise run build:gui`).

## Consequences
- The GUI binary is not built on machines without the headers, including the WSL2 dev box. The
  CI job and the manual runbook (`docs/runbooks/manual-acceptance.md`) cover it.
- Service mode (M14) needs the same launch from the user's session (a user unit or autostart).
